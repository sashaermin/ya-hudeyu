# Единый протокол разработки и передачи сайта

Канонический порядок GitHub checkpoint/handoff для Claude Code, Codex и других разрешённых агентов. Общая точка входа и ограничения — [AGENTS.md](AGENTS.md); единственный roadmap — [IMPLEMENTATION_PROGRESS.md](IMPLEMENTATION_PROGRESS.md), исходное ТЗ — [мастер-ТЗ](project_specs/WEBSITE_MASTER_TZ_2026-10-18.md). Ни один агент не владеет проектом постоянно. Следующий агент работает по GitHub и файлам, без истории чата. Telegram определяется только [AGENT_NOTIFICATION_PROTOCOL.md](AGENT_NOTIFICATION_PROTOCOL.md).

## Возобновление и единственный писатель

1. Проверьте локальный `git status`, известные активные сессии, ответственность в AGENT_HANDOFF.md. Устаревший handoff не доказывает остановку другой сессии. При известном активном писателе не редактировать его ветку; согласовать передачу. Android-сессия Claude работает независимо — её не трогать.
2. `git fetch origin`, определить `work/website-v2`; прочитать этот файл, AGENT_HANDOFF.md, IMPLEMENTATION_PROGRESS.md, AGENT_NOTIFICATION_PROTOCOL.md. Claude читает также CLAUDE.md.
3. Сверить последний проверенный remote SHA (`git ls-remote origin refs/heads/work/website-v2`), локальный HEAD и изменения. Если remote продвинулся, сначала изучить новые коммиты; не перезаписывать их. Не использовать force-push, reset, rebase общей истории или удаление чужой работы.
4. Продолжить **первое незавершённое действие**, не перезапускать проект и не повторять завершённые проверки без изменившихся входов. Не создавать конкурирующие планы/состояния под отдельных агентов.
5. Только один активный писатель сайта. Параллельная работа допустима лишь после явного разрешения владельца, на отдельных ветках и с согласованной интеграцией. Наличие нескольких agent entrypoints само по себе не разрешает одновременную запись.


## Короткие этапы и доказательства

Работать ограниченными проверяемыми порциями с целью, критериями приёмки, соответствующими проверками, commit/push, проверкой remote SHA и точным следующим действием. Сохранять все незакрытые критерии; инфраструктурный чекпоинт не означает готовность релиза.

После проверки обновлять AGENT_HANDOFF.md и IMPLEMENTATION_PROGRESS.md, коммитить и пушить в рабочую ветку, независимо подтверждать remote. Последний SHA в handoff ссылается на предыдущий проверенный checkpoint: самоссылка на содержащий его коммит невозможна; фактический последний commit проверяется через Git. При прерывании сохранять проверенный checkpoint и точную точку продолжения, если это технически возможно; не утверждать сохранение без проверки.

Продолжать автоматически между разрешёнными этапами. Останавливаться только при реальном блокере/обязательном разрешении; независимые задачи выполнять. Не менять приоритеты молча. Проверки подбирать по риску, не выполнять повторно дорогие suites без причины. Не заявлять лимиты агента/мониторинг облака без подтверждённой интеграции.


## Обязательный handoff

[AGENT_HANDOFF.md](AGENT_HANDOFF.md) содержит repository/branch, последний проверенный pushed SHA (или предыдущий verified checkpoint с явным указанием, что текущий SHA нужно получить через Git), последнего достоверного implementing agent, завершённые/текущий этапы, exact next, приоритеты и blockers, build/QA commands, фактические PASS/FAIL/unrun результаты, дизайн/архитектурные решения и их источники, preview/review state, owner approvals и запреты deployment. Детальная история/evidence сохраняется в progress/docs/Git; сокращение текущего handoff не удаляет существенных фактов.

До planned agent replacement: закончить безопасную проверяемую порцию, записать точный следующий шаг и незавершённую проверку, commit/push/ls-remote, подтвердить результат CI отдельно. Не объявлять локальные unpushed изменения переданными. После неожиданного прерывания восстановить remote state; не считать старый handoff доказательством отсутствия другого писателя. Передача не зависит от названия агента; Claude и Codex используют одинаковые файлы, проверки и ветку.

## Проверка холодного старта

Открыть checkout без чата и пройти цепочку AGENTS → этот протокол → handoff → progress/master/QA/notification protocol. Зафиксировать ответы: repository/branch/latest verified remote, что завершено, exact next, команды и ограничения QA, approvals, preview, запреты и порядок checkpoint/handoff. Проверить ссылки и разрешить противоречия до продолжения. `tests/test_handoff_contract.py` обеспечивает базовый regression contract; документальная cold-start симуляция в docs/verification не равна реальному Claude↔Codex transfer. Никогда не заявлять такой transfer, если он не происходил.
