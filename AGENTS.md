# Общие инструкции разработки сайта «Я ХУдЕЮ»

Авторитетный документ для Codex, Claude Code и будущих агентов. GitHub — единый источник состояния. Пользовательские инструкции имеют приоритет. Последнее подтверждённое решение владельца: продолжать сайт автоматически; APK для публичного распространения **не утверждён**.

## Возобновление и единственный писатель

1. Проверьте локальный `git status`, известные активные сессии, ответственность в AGENT_HANDOFF.md. Устаревший handoff не доказывает остановку другой сессии. При известном активном писателе не редактировать его ветку; согласовать передачу. Android-сессия Claude работает независимо — её не трогать.
2. `git fetch origin`, определить `work/website-v2`; прочитать этот файл, AGENT_HANDOFF.md, IMPLEMENTATION_PROGRESS.md, AGENT_NOTIFICATION_PROTOCOL.md. Claude читает также CLAUDE.md.
3. Сверить последний проверенный remote SHA (`git ls-remote origin refs/heads/work/website-v2`), локальный HEAD и изменения. Если remote продвинулся, сначала изучить новые коммиты; не перезаписывать их. Не использовать force-push, reset, rebase общей истории или удаление чужой работы.
4. Продолжить **первое незавершённое действие**, не перезапускать проект и не повторять завершённые проверки без изменившихся входов. Не создавать конкурирующие планы/состояния под отдельных агентов.
5. Только один активный писатель сайта. Параллельная работа допустима лишь после явного разрешения владельца, на отдельных ветках и с согласованной интеграцией. Наличие нескольких agent entrypoints само по себе не разрешает одновременную запись.

## Область и запреты

- Рабочая ветка сайта `sashaermin/ya-hudeyu`: `work/website-v2`, создана от main. Сохранять main, production, CNAME и существующий privacy.html.
- **Без отдельного явного разрешения владельца запрещены**: изменение main, merge, PR, deployment, публикация APK. Обычный checkpoint commit/push рабочей ветки разрешён.
- Android `sashaermin/ya-hudeyu-android` строго read-only, включая `work/activity-progress-v6-4daeaa5`. Не менять его код/ветки/сессию/процессы, не запускать Android-разработку.
- Только Android в контенте сайта. Не предлагать другие клиентские платформы.
- Утверждённое мастер-ТЗ: `project_specs/WEBSITE_MASTER_TZ_2026-10-18.md` — исходный файл владельца, хранить без переписывания. Единственная дорожная карта — IMPLEMENTATION_PROGRESS.md, по этапам этого ТЗ.
- Реальные брендовые ресурсы и токены берутся из Android с SHA и путём в ASSET_SOURCES.json. Не генерировать замену маскоту/скриншотам и не выдумывать APK/функции/отзывы/показатели.
- Код в Android-ветке не доказывает выпуск. APK требует выбора и разрешения владельца, технической проверки и доказательств. До этого download action недоступен, production build блокируется. Визуальное и юридическое одобрение перед выпуском остаются обязательными.
- Не публиковать внутренние отчёты и конфигурацию. Публикуемый артефакт — только `_site`, генерируемый белым списком; никогда не выкладывать корень checkout как готовый сайт.

## Короткие этапы и доказательства

Работать ограниченными проверяемыми порциями с целью, критериями приёмки, соответствующими проверками, commit/push, проверкой remote SHA и точным следующим действием. Сохранять все незакрытые критерии; инфраструктурный чекпоинт не означает готовность релиза.

После проверки обновлять AGENT_HANDOFF.md и IMPLEMENTATION_PROGRESS.md, коммитить и пушить в рабочую ветку, независимо подтверждать remote. Последний SHA в handoff ссылается на предыдущий проверенный checkpoint: самоссылка на содержащий его коммит невозможна; фактический последний commit проверяется через Git. При прерывании сохранять проверенный checkpoint и точную точку продолжения, если это технически возможно; не утверждать сохранение без проверки.

Продолжать автоматически между разрешёнными этапами. Останавливаться только при реальном блокере/обязательном разрешении; независимые задачи выполнять. Не менять приоритеты молча. Проверки подбирать по риску, не выполнять повторно дорогие suites без причины. Не заявлять лимиты агента/мониторинг облака без подтверждённой интеграции.

## Проверки и запуск

- `python3 tools/build.py` → draft `_site` с noindex; `python3 -m http.server 8001 --bind 127.0.0.1 --directory _site`.
- `python3 -m unittest discover -s tests -p 'test_*.py' -v`.
- `python3 -m unittest discover -s .github/scripts -p 'test_*.py' -v`.
- `node --check scripts/site.js` и `node --check scripts/theme.js`.
- Браузерный QA, его зависимости и артефакты — README и docs/QA.md, когда доступны. Нельзя выдавать непроведённые проверки браузеров/устройств за PASS.
- Не создавать git worktree без явной просьбы: облачная задача уже изолирована; использовать существующий checkout.

## Уведомления и отчёты

Следовать AGENT_NOTIFICATION_PROTOCOL.md. Не отправлять Telegram из локальной сессии: отправляет GitHub Actions после push. Используется существующий бот «Я ХУдЕЮ | Dev Reports», repository secrets TELEGRAM_BOT_TOKEN и TELEGRAM_CHAT_ID. Значения никогда не читать/печатать/коммитить. Не создавать нового бота. Проверять только имена/наличие секретов; отсутствие переменных в облачной машине не доказывает отсутствие Actions secrets.

Каждый commit завершать trailer `Agent: Codex`, `Agent: Claude Code` или `Agent: Other agent`, только с достоверной идентификацией. Неизвестный источник — Unknown. Изменения статуса этапа регистрировать в project_specs/agent_events.json; решения владельца — в project_specs/user_actions.json. Для open → resolved записать resolution, чтобы workflow отправил закрытие. Нельзя дублировать события под новым id.

Короткие пользовательские отчёты только по-русски:

Сделано: …
Проверено: …
Далее: …
Требуется от меня: … (только при реальном действии владельца, с краткими нумерованными шагами).
